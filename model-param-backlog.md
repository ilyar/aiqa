# Отложенные дефекты `test=model-param`

Статус: **не реализовано**, по решению пользователя от 2026-09-16.
Текущая правка alpha.14 исправляет `test=compat,sdk`; перечисленные ниже
изменения не входят в неё. Алгоритм параметрических проб и их влияние на
вердикт остаются прежними.

Основание: baseline alpha.14, run_id `01a0aad0-29f1-8cd5-b86e-23cebf856d1e`,
и проверка `internal/suites/modelparam.go`, `internal/assessment/assessment.go`.

## MP01. Недостаточный лимит ошибочно означает неподдерживаемый параметр

`max_completion_tokens=8` для GPT-5.4-mini получил HTTP 400 с сообщением об
исчерпании лимита вывода. AIQA записал `UNSUPPORTED`, поскольку
`probeOutputLimit` трактует любой 4xx как отказ в поддержке параметра.

Будущее исправление: различать неподдерживаемый параметр, неподдерживаемое
значение, недостаточный бюджет, квоту и ошибку доступа. Подбирать ограниченный
набор допустимых бюджетов, сохраняя исходную попытку. Проверять принятие,
валидацию и фактическое действие параметра отдельно.

Приёмка: отказ из-за лимита не превращается в `UNSUPPORTED` или автоматический
PASS; успешный ответ с нарушением лимита по-прежнему обнаруживается. 401/429
и транспортная ошибка не доказывают отсутствие параметра. Тесты — loopback.

## MP02. Исследуемые значения становятся требованиями соответствия

Общий список `reasoning_effort` включает `none`, `minimal`, `low`, `medium`,
`high`, `xhigh`, `max`. Он задан с alpha.0 и не зависит от контракта модели.
Каждый результат становится необязательным требованием; ожидаемый отказ
уменьшает optional-покрытие и приводит к `PASS-WITH-GAPS`.

Для GPT-5.4-mini официально перечислены `none`, `low`, `medium`, `high`,
`xhigh`; поддержка `minimal` и `max` не заявлена.
[Источник](https://developers.openai.com/api/docs/models/gpt-5.4-mini).

Будущее исправление: отделить исследование диапазона от проверки обещанного
контракта. Не прекращать исследовательские пробы только из-за отсутствия
метаданных. Не превращать все `UNSUPPORTED` в N/A. Зафиксировать новую политику
оценки явно, сохранив наблюдения и совместимость отчётов.

Приёмка: документированное неподдерживаемое значение не считается дефектом
протокола; отклонение заявленного значения остаётся проблемой.

## MP03. Сторонние расширения влияют на общую оценку OpenAI

`thinking.enabled/disabled` и `reasoning_split=true/false` исследуются вместе
с параметрами OpenAI. Их отклонение GPT-5.4-mini учитывается как optional gap,
хотя контракт выбранной модели не обещает эти расширения.

Будущее исправление: отдельная область исследовательских расширений с явным
источником контракта. Результат запроса сохраняется независимо от применимости.

Приёмка: отсутствие чужого расширения не ухудшает оценку основного протокола;
заявленная провайдером поддержка продолжает проверяться.

## MP04. Best-effort свойства смешаны с гарантиями протокола

GPT-5.4-mini принял `seed`, но малая выборка не доказала детерминизм. Результат
`WARN` влияет на итоговую совместимость. Между тем API не гарантирует
детерминированность.
[Источник](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create).

Будущее исправление: показывать статистическое наблюдение, условия сравнения,
размер выборки и неопределённость отдельно от контрактных утверждений.
Аналогично проверить `temperature`, `top_p`, `verbosity`.

Приёмка: отсутствие статистического эффекта не выдаётся за доказанное
нарушение; нельзя повторять пробу до случайного PASS или скрывать WARN.

## MP05. Anthropic model-param остаётся честным stub

Для обеих Anthropic моделей baseline содержит
`aiqa.model_param.implementation = SKIP`: соответствующий анализ AIQA не
реализован и не выполнял запросов. Это недоработка AIQA, не отказ провайдера.

Будущее решение: отдельная реализация по контракту Anthropic либо явно
согласованный объём baseline без `model-param`. Нельзя просто удалять SKIP
из текущего объединённого запуска ради PASS.

Приёмка: пока реализации нет, запрос `test=model-param` сохраняет видимый
implementation gap. Запуск только `test=compat,sdk` не наследует этот gap.

## MP06. Стоимость исследования контекстного окна

Это отдельное улучшение, не подтверждённый дефект совместимости. В baseline
параметрический прогон GPT-5.4-mini учёл 3 842 806 context-probe tokens.
Такая исследовательская нагрузка отличается от короткого compat baseline.

Будущее решение: явно показывать объём, бюджет и прогресс исследования;
согласовать отдельный режим глубокой проверки границы контекста. Не считать
остановку по бюджету доказанным пределом модели.

Приёмка: бюджет и фактически измеренная граница различимы в отчёте;
увеличение бюджета требует явного решения, а не скрытого повторного запуска.
