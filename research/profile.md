Коротко: два файла нужны не из-за разных реализаций тестов, а из-за двух разных критериев совместимости.

- profile/google-genai-compat-2026-09.json:32 — основной современный профиль. Models + Interactions обязательны, а generateContent
  проверяется как дополнительная возможность.

- profile/google-genai-generate-content-compat-2026-09.json:16 — строгий профиль для шлюзов, реализующих старый контракт. Здесь
  обязательны Models + generateContent + stream, а Interactions необязателен и по умолчанию выключен.

Например, google.generate-content.basic в первом профиле имеет required: false, а во втором — required: true. Для Interactions ситуация
обратная. Именно поле required определяет попадание требования в core и влияет на итоговый verdict (internal/assessment/
assessment.go:415).

Можно ли объединить в один google-genai-compat-2026-09.json?

Физически — да. Более того, основной профиль уже содержит практически все проверки второго профиля: 60 probes против 59. Но без потери
смысла в текущем aiqa.profile.v3 — нет, потому что у каждой проверки есть только одно статическое значение required, а у модуля — одно
default_enabled (internal/profile/profile.go:17).

При простом объединении придётся выбрать один плохой компромисс:

- сделать обязательными обе поверхности — шлюзы только с Interactions или только с generateContent будут считаться несовместимыми;
- сделать обе необязательными — verdict «Google GenAI compatible» станет слишком слабым;
- оставить обязательным только Interactions — получится уже существующий основной профиль, но исчезнет возможность строго доказать
  совместимость с generateContent;

- оставить обязательным только generateContent — современный профиль фактически превратится во второй.

Итог: удалить второй файл и оставить один можно, если строгий отдельный verdict для generateContent вам не нужен. Если он нужен, два
логических профиля необходимо сохранить. Для сокращения дублирования лучше вынести общий каталог probes/modules в базовое описание,
оставив две небольшие policy-надстройки. Это потребует изменения схемы и загрузчика, но сохранит правильную семантику.
